# 六模型推理交接（分享版）

版本：2026-10-20。本文由内部完整交接文档重新整理，移除了内部机器地址、账号路径、作业ID和端点状态。所有 `/path/to/...`、SSH alias和端口配置均需接收方填写；不保证原服务仍在线。

## 1. 交付内容和使用边界

六模型分别为 FastWAM、OpenWAM Alpha、Ours Joint、Ours Tri、Ours Coarse-to-fine、Pi0.5。共享一个TCP v4协议，两份本体client分别为G2和Piper。

本包包含两份客户端的推理相关源码、必要的Piper replay/IK模块、协议/映射实现、脱敏配置和回环测试。它不是完整的G2/EgoAV项目，不含server模型代码、GPU环境、权重、tokenizer、文本/VAE缓存、原始数据或机器人驱动。需从模型维护方取得完整server仓库及训练sidecar。

`clients/g2` 来自已保存的G2提交；`clients/piper` 以已保存提交为底，更新为2026-10-20读取的replay/IK源码。G2的五个核心脚本、Piper入口和robot执行模块均已与现场文件SHA256比对一致。版本细节见 `版本与验证边界.md`。

## 2. 统一接口与模型差异

| 模型 | `--model` | server入口（在完整server仓库中） | 默认采样 | 推理compile |
|---|---|---|---:|---|
| FastWAM | `fastwam` | `scripts/mixed76_server/fastwam/serve_v4.py` | 20 | 否 |
| Alpha | `alpha` | `scripts/mixed76_server/alpha/serve_tcp_v4.py` | 10 | 是 |
| Joint | `joint` | `python -m openwam.deploy.ours.tcp_v4` | 20 | 否 |
| Tri | `tri` | 同上 | 20 | 否 |
| Coarse-to-fine | `coarse_fine` | 同上 | 20 | 否 |
| Pi0.5 | `pi05` | `scripts/mixed76_server/pi05/serve_pi05_v4.py` | 10 | 否 |

这里记录的是部署推理设置。训练使用compile不代表推理也开compile。Ours旧 `openwam.deploy.ours.server` 是WebSocket服务，不能与TCP client混用。

网络统一传物理76D状态与动作，输出 `[32,76]`，`dt_s=0.05`；本体未使用槽位为0，mask显式返回。server负责图像处理、文本指令、归一化和反归一化，client负责本体转换、动作前缀、反馈和执行。Joint67/TriJoint67是历史架构名称，当前混训接口为76D，Tri使用Pose30＋Hand46。

## 3. server需要哪些文件

一个完整run目录至少包含：

```text
checkpoint_step_30000.safetensors
config.yaml
model_contract.json
normalization_stats.npy
normalization_contract.json
```

还需上述文件引用的Wan视频/VAE权重、文本cache manifest和张量、Pi tokenizer、Alpha Foundation模型配置等。移动checkpoint目录不会自动修复其中的绝对路径。接收方应按合同迁移资产并由模型维护方验证，不要只拷贝safetensors。

server需要匹配的GPU Torch/CUDA及外部模型实现。`requirements-offline.txt`只用于测试client；不能用于替代server的完整环境。Pi需匹配openpi、tokenizer及protobuf依赖，FastWAM需模型实现和其 `fastwam_client` 支持模块，Ours还依赖完整仓库中的数据合同和文本cache加载器。

## 4. 六种server启动命令

在已经分配的一张GPU环境内设置公共变量。以下都是部署占位值：

```bash
export SERVER_CODE_ROOT=/path/to/full-server-repository
export RUNTIME_ENV=/path/to/matched-runtime/runtime_env.sh
export EXTRA_PYTHONPATH=/path/to/model-dependencies
export SERVER_HOST=0.0.0.0
SERVER_LAUNCH=/path/to/Mixed76_Inference_Handoff/tools/server_launch_examples.sh
bash "$SERVER_LAUNCH" --help
```

`runtime_env.sh`需定义 `RUNTIME_PYTHON` 和匹配依赖。`EXTRA_PYTHONPATH` 可用冒号追加多个路径，不应随意换成其他版本。一个进程只暴露一张已分配GPU；调度worker保留调度器给定的 `CUDA_VISIBLE_DEVICES`。

下面每次选一条；每个服务使用独立run和output目录。所有模板默认30k权重；Alpha/Pi的现有代码固定读取该文件名，改checkpoint版本须由维护方适配并验证身份。

```bash
# FastWAM：当前实现只监听loopback，必须经运行环境本身的SSH转发
INFERENCE_RUN_DIR=/path/to/fastwam-run INFERENCE_OUTPUT=/path/to/new-output/fw DATA_ROOT=/path/to/source-metadata bash "$SERVER_LAUNCH" fastwam

# Alpha
INFERENCE_RUN_DIR=/path/to/alpha-run INFERENCE_OUTPUT=/path/to/new-output/alpha bash "$SERVER_LAUNCH" alpha

# Joint
INFERENCE_RUN_DIR=/path/to/joint-run INFERENCE_OUTPUT=/path/to/new-output/joint bash "$SERVER_LAUNCH" joint

# Tri
INFERENCE_RUN_DIR=/path/to/tri-run INFERENCE_OUTPUT=/path/to/new-output/tri bash "$SERVER_LAUNCH" tri

# Coarse-to-fine
INFERENCE_RUN_DIR=/path/to/c2f-run INFERENCE_OUTPUT=/path/to/new-output/c2f bash "$SERVER_LAUNCH" coarse_fine

# Pi0.5
INFERENCE_RUN_DIR=/path/to/pi05-run INFERENCE_OUTPUT=/path/to/new-output/pi05 bash "$SERVER_LAUNCH" pi05
```

FastWAM默认18849，Alpha8866，Ours三模型8861，Pi8858。可用 `SERVER_PORT`覆盖。Ours三服务若在同一主机上运行必须用不同端口。FastWAM的loopback不能通过普通 `podIP:port`连接；SSH要落到实际监听环境。其余服务可使用可达的podIP＋端口。

如需在调度平台运行，向维护方确认当前submit接口、队列和GPU配额，将 `bash server_launch_examples.sh 模型`作为worker命令；本包不包含内部调度配置。新worker的IP会变化，要同步更新两端client配置。

启动后先看输出目录 `info.json`及日志，再进行记录观测测试。冷启动的编译/预热不应直接放进实时执行回路。Ctrl+C可结束前台server；调度任务使用平台正常停止入口，不用全局kill。

## 5. 安装两份client并填端点

G2：将 `clients/g2/scripts/` 中的文件合并到兼容G2项目的 `scripts/`。Piper：将 `clients/piper/src/infer/` 和明确列出的 `src/replay/` 文件合并到兼容EgoAV项目同名目录。先查看diff；不要覆盖本机的机械臂映射、recording mapping和SDK。

G2执行另需 `run_ours_client.py`、`robot_wrapper.py`、`sharpa_hands.py`、Sharpa配置、Pico和机器人SSH路由。Piper执行另需 `src/record`、`src/teleop`、相机/CAN和三follower映射、Piper SDK。上述硬件项目不在包内。

G2配置位置为 `<G2_ROOT>/configs/<model>_mixed76_v4.json`；Piper为 `<PIPER_ROOT>/src/infer/mixed76_configs/<model>_mixed76_v4.json`。

例如为Joint创建配置：

```bash
# 在G2项目根目录
cp configs/mixed76_examples/joint_mixed76_v4.example.json configs/joint_mixed76_v4.json

# 在Piper项目根目录
cp src/infer/mixed76_configs/joint_mixed76_v4.example.json src/infer/mixed76_configs/joint_mixed76_v4.json
```

编辑副本中的 `ssh_host`、`server_host`、`server_port`。每份模板的8857只是占位端口，必须以实际server监听为准。模型字段保留相应model名称。

```json
{"model":"joint","protocol_version":4,"ssh_host":"YOUR_SERVER_ALIAS","server_host":"127.0.0.1","server_port":8861}
```

`ssh_host`是client所在主机上的SSH别名，client自动建立和关闭隧道。`server_host`相对于SSH目标解释；127.0.0.1不是client自身。可通过 `--remote-config /path/to/custom.json`覆盖默认文件。配置好已知主机和公钥，不在分享包中分发私钥。

## 6. Piper启动：记录观测与连续Book

先进入完整EgoAV项目：

```bash
cd /path/to/egoav
PIPER_PYTHON=/path/to/piper-python
"$PIPER_PYTHON" -m src.infer.mixed76_client --help
```

无运动推理：

```bash
"$PIPER_PYTHON" -m src.infer.mixed76_client --model joint --task book --observation /path/to/book_observation.npz --output /path/to/book_actions.npy
```

NPZ包含 `state` 和 `head_rgb`：Piper原生状态23D或已编码76D，RGB uint8原图。实际模型验收使用匹配任务的 `[480,640,3]` 图像。不要将basket观测换个task名当成book验收。

连续推理并执行，每次只选一条：

```bash
"$PIPER_PYTHON" -m src.infer.mixed76_client --model fastwam --task book --execute --cycles 100000 --steps 32 --max-response-age 5
"$PIPER_PYTHON" -m src.infer.mixed76_client --model alpha --task book --execute --cycles 100000 --steps 32 --max-response-age 5
"$PIPER_PYTHON" -m src.infer.mixed76_client --model joint --task book --execute --cycles 100000 --steps 32 --max-response-age 5
"$PIPER_PYTHON" -m src.infer.mixed76_client --model tri --task book --execute --cycles 100000 --steps 32 --max-response-age 5
"$PIPER_PYTHON" -m src.infer.mixed76_client --model coarse_fine --task book --execute --cycles 100000 --steps 32 --max-response-age 5
"$PIPER_PYTHON" -m src.infer.mixed76_client --model pi05 --task book --execute --cycles 100000 --steps 32 --max-response-age 5
```

`cycles`必须是正整数，0会被拒绝。100000轮通常用Ctrl+C手动结束。`steps 32`表示每轮执行32帧后重新观测，与server去噪步数不同。启动 `--execute` 会先归位三只follower；即便steps1也会发生归位。

当前Piper入口默认观测年龄上限5秒，包含推理和IK。取消了旧2mm/1°的普通IK残差拒绝；输入合法性、关节范围和求解有限性仍在。现场2026-10-20的replay常量是位置跟踪70mm、夹爪跟踪70mm；推理monitor调用 `check_position=False`，因此推理主要保留姿态/关节/夹爪/反馈时序等检查。带 `max_step_deg` 的独立replay连续IK路径另有0.1mm/0.1°精度判定，不要与普通推理IK混淆。移机要按接收方机器人重新确认这些设置。

## 7. G2启动：记录观测与连续Yifu

```bash
cd /path/to/agibot_inference
G2_PYTHON=/path/to/g2-python
"$G2_PYTHON" scripts/run_mixed76_client.py --help
"$G2_PYTHON" scripts/run_mixed76_client.py --embodiment g2 --model joint --task yifu --observation /path/to/yifu_observation.npz --output /path/to/yifu_actions.npy
```

G2原生状态为61D，入口也接受已编码76D。连续推理并执行，每次只选一条：

```bash
"$G2_PYTHON" scripts/run_mixed76_client.py --embodiment g2 --model fastwam --task yifu --execute --iterations 100000 --steps 32 --max-response-age 2
"$G2_PYTHON" scripts/run_mixed76_client.py --embodiment g2 --model alpha --task yifu --execute --iterations 100000 --steps 32 --max-response-age 2
"$G2_PYTHON" scripts/run_mixed76_client.py --embodiment g2 --model joint --task yifu --execute --iterations 100000 --steps 32 --max-response-age 2
"$G2_PYTHON" scripts/run_mixed76_client.py --embodiment g2 --model tri --task yifu --execute --iterations 100000 --steps 32 --max-response-age 2
"$G2_PYTHON" scripts/run_mixed76_client.py --embodiment g2 --model coarse_fine --task yifu --execute --iterations 100000 --steps 32 --max-response-age 2
"$G2_PYTHON" scripts/run_mixed76_client.py --embodiment g2 --model pi05 --task yifu --execute --iterations 100000 --steps 32 --max-response-age 2
```

G2使用iterations，Piper使用cycles。G2仍是2秒默认时限。G2启动执行前调用startup_reset，然后连接机器人和Sharpa手；默认Pico位置由用户主目录推导，可用 `--pico-root`、`--robot-ssh`、`--hands-config`覆盖。

## 8. 模型/任务切换与指令

先退出当前client，再改model重连；只换client模型不需要重启所有server。任务与本体对应：Piper为book/basket；G2为yifu/dengpao/diguan。任务改动也要对应现场布置或记录观测。

client通过 `task` 让server选 `info.prompts`中的训练指令，不在client临时改写或翻译。五条指令及原始协议见 `protocol/PROTOCOL_V4_original.md`的合同说明；英文全文另列于 `任务指令.md`。

32帧×0.05秒表示1.6秒动作跨度；推理、网络和IK耗时还在其外，不等于每个新观测都以20Hz更新。当前没有独立“实时观测并推理、但完全不执行”的CLI；不用 `--execute --steps 1`模拟只读。

## 9. 验收和故障

接通顺序：server加载成功→读取info核对model/protocol/checkpoint/normalization/deployment_id→记录观测返回有限 `[32,76]`且mask正确→本体转换→现场控制检查。TCP回环测试通过只说明协议/转换代码，不证明真实模型或任务成功。

动作执行前确认反馈、坐标系、TCP、单位、归位路径、限位、工作区、现场操作员和急停。Piper米/毫米接口与训练源单位必须对应；info中的 `physical`不等于坐标和单位已独立认证。

错误定位：SSH失败先查alias/路由/认证；TCP超时查监听与新podIP；协议失败查v4/模型身份；观测过期查冷启动、网络和IK；tracking异常查具体follower的目标与反馈。Ctrl+C退出client后确认实体停止，软件hold请求不是硬件急停。

## 10. 本包没有做什么

打包过程中没有修改生产代码、阈值或端点，没有启动六模型server，没有执行机器人动作，也没有上传到外部服务。分享版移除了内部地址，不提供“当前在线”保证。接收方需要填写部署参数，并在自己的环境复验。
